# Docker rehearsal, 2026-10-23

## Scope and release decision

The user has not selected a production provider. This work is local Docker QA,
not a deployment. No remote push, AWS change, real Stripe transaction, real email
or write to the recovered database is part of this rehearsal.

All three repositories use `feature/docker-release-qa-20261023`. The runnable
stack and commands are in `deploy/docker-qa/README.md`. Source branches should
be reviewed together; no production configuration should be copied from QA.

- Go toolchain/image: 1.26.10. Security updates: pgx 5.9.2, x/net 0.60.0,
  x/text 0.42.0, gRPC 1.83.1 and the OpenTelemetry 1.45.0 family. Transitive
  module versions are recorded in go.mod/go.sum.
- Bun 1.3.8, Better Auth 1.6.22 (deliberately not a feature upgrade to 1.7),
  Hono 4.13.13, Drizzle 0.45.4/kit 0.31.11 and Zod 4.6.7.
- Fresh production dependency stage with optional peers omitted. The old
  in-place production install retained development packages. The new image
  asserts that drizzle-kit/esbuild are absent; runtime inspection also checks
  TypeScript is absent. Builder/test images retain their required tools.
- Client/admin Dockerfiles use Node 24.16.0 and Next standalone output,
  non-root users, clean build contexts and packaged static/public assets.
- Both frontends retain Tailwind 3. The selector parser is narrowly overridden
  to 7.1.6 rather than migrating the style system to Tailwind 4. Admin's
  Browserslist and client's brace-expansion receive compatible lock updates.
- Health now checks the primary database rather than accepting a healthy read
  replica as proof that writes work. Upstream HTTP 5xx is classified down.
- The financial assertion compares decimal values, not two versus eight
  textual decimal places. No payout formula is changed.
- The previously unexecuted full binary-ban fixture now uses separate
  parameterized statements, purchase inflows/R1 activity, and current blacklist
  migrations. Its assertions still require zero binary payout to the banned
  affiliate, $50 to the company, and consumption of the original package cap.
- CI no longer treats full Go integration failures as non-blocking before
  publishing images. This workflow was NOT triggered remotely.

## Isolation

The stack uses its own tmpfs Postgres and disposable Redis. It does not mount
the recovered database, production env files or host credentials. All service
tokens/Stripe keys are deliberately synthetic. Application services have an
internal Docker network; only a credential-free fixed-upstream HTTP gateway
bridges loopback preview ports. An external HTTPS request from the client
container was rejected. This is an isolation check, not a firewall pentest.

Go integration tests use the host Docker socket to create their own isolated
Timescale/Postgres databases. The socket is privileged and should only be used
with trusted test code. Do not run global Docker cleanup commands.

## Still Required Before Production

- Client's global JS/TypeScript check still reports 412 pre-existing errors.
  Next production builds and focused tests pass, but the global typecheck is
  NOT green; no checks were disabled to hide this.
- Real Cognito identity/OTP, email delivery (including Outlook), Stripe sandbox
  checkout/webhooks/refunds, BMP and SES require dedicated staging credentials
  and integration tests. Docker does not prove delivery to real inboxes.
- Actual production hardware, ingress/TLS, strict identity verification,
  credential rotation, observability, durable backup/restore and a realistic
  1,100-concurrent-user workload remain unverified.
- QA auth SQL only mirrors the app's declared schema for a fresh database.
  Production auth migrations must be explicitly reviewed and applied through
  the owned migration process, never through this QA bootstrap.
- The historical forest audit and migration 68 are not a production data fix.
  No affiliates were moved or removed, and no recovered data was rewritten.
